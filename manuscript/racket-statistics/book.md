#### 0.1 統計を学ぶ楽しさとボートレースという題材

統計学やデータサイエンスと聞くと、難解な数式やギリシャ文字が並ぶ教科書を想像して身構えてしまうかもしれません。しかし、統計の本当の面白さは**「手元にあるデータから、まだ誰も気づいていない傾向やルールを掘り起こす探偵のような体験」**にあります。

本書では、その最高の題材として**「ボートレース（競艇）」のデータ**を扱います。
ボートレースは、6艇のボートが1周600mのコースを3周して着順を競う競技です。一見するとシンプルな競技ですが、そこには以下のような多様なデータが存在します。

* **コース（枠番）の有利不利**: 「1コースが圧倒的に強い」とされるが、会場（全国24場）や風向き・波の高さでどう変わるか？
* **レーサーの成績**: 全国勝率、現地勝率、平均スタートタイミング（ST）。
* **モーターの性能**: レースごとに抽選で割り振られるモーターの複勝率（連対率）。

これらのデータをプログラミングを使って集計・分析し、「どのデータがレースの勝敗に最も影響を与えているか」を解き明かしていくプロセスを通じて、統計学の実利を楽しく学びます。

#### 0.2 R/Pythonに匹敵するRacketのデータ解析力：「RacketFrames」の紹介

データ分析といえば、Python（Pandas）や R 言語が有名です。しかし、プログラミング初心者にとって、Python や R の環境構築や独特な文法ルール（複雑なインデントや様々な記号の使い分け）は、データ分析の本質にたどり着く前の大きな壁になります。

本書で採用する **Racket** は、教育用として洗練された非常に美しい言語です。
文法がシンプルで一貫しており、環境構築も「DrRacket」というソフトを1つインストールするだけで完了します。

「でも、RacketでPythonのような本格的な表計算ができるの？」と疑問に思うかもしれません。
安心してください。本書では、PythonのPandasやRのデータフレームに匹敵する強力なデータ解析ライブラリ **「RacketFrames」** を導入します。

```racket
#lang racket
(require racketframes)

;; CSVファイルを1行でデータフレーム（表データ）として読み込む
(define df (read-csv "races.csv"))

;; 会場ごとにグループ化して平均勝率を一発で集計する
(df-groupby df "stadium" '(("win_rate" . mean)))
```

このように、複雑なプログラムを書くことなく、**わずか数行の直感的なコードで大量のレースデータを自由自在に操作・集計**できるようになります。

#### 0.3 DrRacket のインストールと最初の準備

まずは、開発環境である **DrRacket** を準備しましょう。

1. [Racket 公式サイト](https://download.racket-lang.org/) にアクセスし、お使いのOS（Windows / Mac / Linux）に合ったインストーラをダウンロードして実行します。
2. インストールが完了したら、**DrRacket** を起動します。
3. 画面は上下（または左右）の2つのエリアに分かれています。
   * **定義ウィンドウ（上のエリア）**: プログラムコードを書き保存する場所。
   * **相互作用ウィンドウ（下のエリア / REPL）**: 式を入力すると、その場で計算結果が返ってくる対話画面。
4. ファイルの先頭に、使用する言語を指定するおまじないを書きます。

```racket
#lang racket
```

画面上部の **「Run」** ボタン（または Ctrl+R / Cmd+R）を押すと、プログラムが読み込まれます。

#### 0.4 式と評価規則：Racket のシンプルな文法

Scratch では「(10) + (20)」のようなブロックを組み立てました。Racket での計算も全く同じです。
Racket のコードは、すべて **` (演算子 引数1 引数2 ...) `** という統一された形で書きます。

```racket
#lang racket

(+ 10 20)      ; => 30
(* 5 8)        ; => 40
(- 100 35)     ; => 65
(/ 50 2)       ; => 25
```

* **開き括弧 `(` の直後には、必ず行いたい計算（演算子や関数名）** を書きます。
* 値と値の区切りは**スペース**で行います（カンマ `,` は使いません）。
* コメント（プログラムとして実行されないメモ）は半角セミコロン `;` から始めます。

複数の計算を組み合わせる「ネスト（入れ子）」も簡単です。

```racket
;; 3 と 4 を掛けた結果に、10 を足す
(+ 10 (* 3 4))  ; => 10 + 12 = 22
```

計算は、最も内側の括弧 `(* 3 4)` から順番に評価されていきます。

## 第1章　Racketプログラミングの第一歩

> **この章のゴール**  
> Racket の基本文法（変数定義・関数定義・条件分岐・リスト・ハッシュ）をマスターし、ボートレースの基礎ルールとドメイン知識を理解してプログラミングの第一歩を踏み出す。  
> **使用言語**: Racket（`#lang racket`）  

#### 1.1 ScratchからRacketへ：ブロックとテキストコードの対応

Scratch などのビジュアルプログラミングを経験した方にとって、テキスト言語は難しく見えるかもしれません。しかし、行っている**考え方の構造は全く同じ**です。

まずは Scratch の代表的なブロックと、Racket での書き方の対応を見てみましょう。

| 行いたいこと | Scratch ブロックのイメージ | Racket コード |
| :--- | :--- | :--- |
| **値の計算** | `(10) + (20)` | `(+ 10 20)` |
| **変数に値を保存** | `[勝率] を (0.75) にする` | `(define win-rate 0.75)` |
| **関数の定義** | `定義 [2倍する (x)]` | `(define (double x) (* x 2))` |
| **条件分岐** | `もし <(x) > (50)> なら...` | `(if (> x 50) "合格" "不合格")` |
| **リストの作成** | `リスト [艇番] を作成` | `(define boats '(1 2 3 4 5 6))` |

Racket では、名前の間にハイフン（`-`）を使うのが標準的なスタイルです（例： `win-rate`, `calc-score`）。

#### 1.2 基本的な計算と関数：DrRacketでの動かし方

プログラムを再利用可能な部品にするために、**「関数（function）」** を作ります。

Racket で関数を定義する基本形は次のとおりです。

```racket
#lang racket

;; 関数の定義: (define (関数名 引数1 引数2 ...) 実行する計算)
(define (calc-payout-rate total-sales total-payout)
  (/ total-payout total-sales))

;; 関数の呼び出し
(calc-payout-rate 10000 7500)  ; => 3/4 または 0.75
```

##### 複数の条件分岐：`cond` 式
「もし1号艇ならA、2号艇ならB...」のように条件が複数ある場合は、`cond` 式を使うと綺麗に書けます。

```racket
(define (get-course-color boat-number)
  (cond
    [(= boat-number 1) "白"]
    [(= boat-number 2) "黒"]
    [(= boat-number 3) "赤"]
    [(= boat-number 4) "青"]
    [(= boat-number 5) "黄"]
    [(= boat-number 6) "緑"]
    [else "不明な艇番"]))

(get-course-color 1)  ; => "白"
(get-course-color 4)  ; => "青"
```

各条件は角括弧 `[...]` で囲み、最後にどの条件にも当てはまらない場合の処理を `[else ...]` に書きます。

#### 1.3 リストとハッシュの基本：データをまとめる方法

複数のデータを扱って統計処理を行うには、データをひとまとめにする構造が必要です。Racket では主に **リスト（List）** と **ハッシュテーブル（Hash）** を使います。

##### 1. リスト（List）
同じ種類のデータ（例えば6艇の艇番や、レースの着順）を順番に並べたものです。

```racket
;; リストの作成
(define boat-numbers '(1 2 3 4 5 6))
(define racer-names '("峰" "毒島" "瓜生" "白井" "桐生" "馬場"))

;; リストの要素数を得る
(length boat-numbers)  ; => 6

;; リストの先頭要素を取得する
(first racer-names)    ; => "峰"

;; リストの2番目以降を取得する
(rest racer-names)     ; => '("毒島" "瓜生" "白井" "桐生" "馬場")
```

##### 2. ハッシュテーブル（Hash Table）
「キー（名前など）」と「値（データ）」をペアにして保存する辞書のような構造です。

```racket
(define racer-win-rates
  (hash "峰" 0.85
        "毒島" 0.81
        "白井" 0.78))

(hash-ref racer-win-rates "峰")  ; => 0.85
```

#### 1.4 【基礎知識】超わかりやすいボートレース（競艇）のルールと仕組み

これから扱うボートレースデータの背後にあるドメインルール（ドメイン知識）を直感的に理解しましょう。

##### 1. レースの基本情報
* **6艇で争う**: レースは常に **1号艇（白）〜6号艇（緑）** の6艇で行われます。
* **コース**: 1周600mの楕円形コースを **3周（合計1,800m）** 走ります。

##### 2. スタートのルール（超重要！）
ボートレースは「ヨーイドン」で止まった状態からスタートするのではなく、助走をつけてスタートラインを通過する **「フライングスタート方式」** を採用しています。

* 大時計が **0秒になった瞬間〜1秒以内** にスタートラインを通過しなければなりません。
* **0秒より早すぎる $\rightarrow$ フライング (F)**: 反則失格となり、その艇に賭けられた舟券代は全額返還（返還欠場）されます。
* **1秒より遅すぎる $\rightarrow$ 出遅れ (L)**: 失格扱いとなり、勝てる見込みがなくなります。

> **💡 なぜ1号艇（最内コース）が圧倒的に有利なのか？**  
> 最短距離でスタートラインを通過でき、第1ターンマーク（最初のコーナー）を先頭で旋回できるためです。

##### 3. コース取りのルール
* ピットアウト（待機場所から飛び出す）後、スタートまでの「待機行動」で進入コースが決まります。
* 基本は枠番通りの「枠なり進入（1号艇が1コース）」ですが、ベテラン選手（イン屋）が外枠から強引に内側のコースを奪いにいく「深イン」などの駆け引きが発生します。

##### 4. 勝敗と賭け方
* 1着〜6着まで着順が決まり、賞金も順位順に支払われます。
* **2連単**: 1着・2着の組合せを順番通り当てる。
* **3連単**: 1着・2着・3着を完全な順序で当てる（一番人気で一番難しい。**平均配当は約7,000円〜8,000円**）。

> [!NOTE]
> ### ⚠️ 【分析スコープに関する重要前提】自然環境要素（天候・風向風速・波高など）の扱いについて
> 
> ボートレースでは風向や波の高さなどの自然条件が展開に影響を与えますが、**`turnmark/api` をはじめとする一般的なデータ配信基盤（JSON/API）には天候・風向・風速・波高・水温などの環境データは含まれておりません。**
> 
> したがって、**本書の統計モデルおよびコードでは天候・風などの自然環境要素は対象外（スコープ外）として扱い**、選手成績・枠番・モーター2連対率・確定着順といった **構造的数値データに集中して分析を行う方針** を採っています（※この前提は第2章以降でも繰り返し明記します）。

#### 1.5 章のまとめ：三角ロジックによる整理

* **【主張 (Claim)】**: Racketの基本文法とボートレースの基礎ドメイン知識を組み合わせることで、構造化数値データに基づくデータサイエンスの土台を構築できる。
* **【事実・データ (Fact)】**: Racketの`define`や`cond`、リスト・ハッシュ構造を用いたコード（`code/ch01-basics.rkt`）と、`turnmark/api`における自然環境要素の不保持仕様。
* **【論拠・理由付け (Reasoning)】**: 自然環境などの確率的ノイズをモデル対象外とし、6艇枠なり・フライングスタート等の確定ルールと構造的数値に絞ることで、プログラム処理の再現性と一貫性が担保されるため。

## 第2章　ボートレースのデータを集める（データ収集）

> **この章のゴール**  
> Webや外部ツール（`curl`）およびオープンAPI（`turnmark/api`）を活用してボートレースのデータ（JSON/HTML）を手元に取得し、プログラムで扱える構造化CSVへと変換する。  
> **【本線】**: `turnmark/api` から用途に合わせたタスクランナーメニュー（`today`, `json`, `range`）で日付別 JSON (`data/raw/YYYYMMDD.json`) を取得・蓄積保存し、Racket 標準の `(require json)` で全自動スキャン＆蓄積パース（`code/ch02-json-parser.rkt`）。  
> **【参考・応用】**: 公式Webサイト（HTML生データ）の `curl` 取得と正規表現パース（`code/ch02-html-parser.rkt`）。  
> **使用技術**: Racket `net/url`, `json`, `curl`, `mise` タスクランナー (`mise run data:download:today`, `mise run parse:json`, `mise run parse:html`)

本章では、統計分析の土台となる「データ収集」の手法を学びます。現在ではボートレースのデータをオープンデータとして JSON 形式で配信する **`turnmark/api`** が存在するため、本章では **「用途に応じたダウンロードタスクで JSON データを手元に蓄積保存し、Racket で一括パースする手法」を本線** として解説します。

また、従来手法や他言語ライブラリ（`pyjpboatrace` 等）でよく行われている **「公式Webサイトから HTML 生データをダウンロードしてパースする手法」** も発展学習として併せて解説します。

> [!NOTE]
> **⚠️ 【第1章に続き再確認】自然環境要素（天候・風向・風速・波高など）の扱いについて**  
> 第1章でも触れた通り、`turnmark/api` を含む標準的なデータ API には天候（晴れ・雨）、風向・風速、波高、水温などの【自然環境要素】は含まれておりません。そのため、**本書ではこれら天候や風などの自然環境要素はモデルに含めずスコープ外として扱い**、艇番・選手成績・モーター2連対率・確定着順といった **構造的データに特化して分析を進めます。**

#### 2.1 【本線】オープンデータ API から日付指定・期間一括 JSON を取得・蓄積してパースする

最もしっくりかつ確実なデータ収集法は、すでに構造化されて提供されている **JSON データ API** を活用することです。

##### 1. `turnmark/api` と目的別タスクランナーメニュー
[turnmark/api](https://github.com/turnmark/api) では、日付ごとのレースデータ（出走表・直前情報・確定着順）が以下の URL で配信されています。

- **本日のデータ**: `https://turnmark.github.io/api/v1/today.json`
- **日付指定データ（2026年01月01日以降）**: `https://turnmark.github.io/api/v1/YYYY/YYYYMMDD.json`

本書のリポジトリでは、用途や学習段階に応じて使い分けられる **4 種類のデータダウンロードメニュー（タスクランナー）** を用意しています。

| タスクコマンド | 用途・機能概要 | 日付指定プロンプト | 保存ファイル名 |
|---|---|---|---|
| **`mise run data:download:today`** (または `data:download`) | **【本日即時取得】** 日付確認なしで本日のデータのみを一発で全自動ダウンロード | なし（即時実行） | `data/raw/YYYYMMDD.json` |
| **`mise run data:download:json`** | **【単日対話指定】** プロンプトで日付を確認・選択（指定の過去日にも変更可） | あり（デフォルト: 本日） | `data/raw/YYYYMMDD.json` |
| **`mise run data:download:range`** | **【過去期間一括】** 開始日と終了日を指定して過去複数日分を一括ダウンロード蓄積 | あり（開始日〜終了日） | `data/raw/YYYYMMDD.json` |
| **`mise run data:download:official`** | **【HTML参考】** ボートレース公式Webサイトから 1 レース分の HTML を取得 | なし（桐生1R固定） | `data/raw/racelist_sample.html` |

---

##### 2. ダウンロードタスクランナーの具体的な使い方

###### ① 本日分のみをサクッと一発取得したいとき (`mise run data:download:today`)
日付の入力や確認画面を出さず、「とにかく今日のボートレースデータを取得したい」場合に最適です。

```bash
# 本日分のレースデータを無確認で一発取得
mise run data:download:today
```

```text
本日のボートレースデータ (20260726) を自動ダウンロードしています...
ダウンロード完了: data/raw/20260726.json
```

###### ② 特定の過去日を指定して取得したいとき (`mise run data:download:json`)
対話プロンプトが表示され、日付を入力・変更できます（そのまま Enter で本日分）。

```bash
# 日付を確認・指定して単日データ取得
mise run data:download:json
```

```text
取得対象の日付を入力してください (YYYYMMDD) [デフォルト: 20260726]: 20260501
ボートレースデータ (対象日: 20260501) をダウンロードしています...
ダウンロード完了: data/raw/20260501.json
```

###### ③ 過去数日〜数ヶ月分のデータを一括蓄積したいとき (`mise run data:download:range`)
開始日と終了日を指定し、まとめデータを順次ローカルフォルダ `data/raw/` に蓄積します。

```bash
# 過去の期間を一括指定して連続ダウンロード
mise run data:download:range
```

```text
==========================================================
 期間指定ダウンロード開始: 20260701 〜 20260705
```

> [!IMPORTANT]
> ### 🔥 【統計学の真髄】なぜ「今日だけのデータ」では役に立たないのか？ ＆ 日付列 (`date`) の重要性
> 
> 初学者がよく陥る罠として、**「今日のレース結果だけダウンロードすれば、分析や予想ができるのでは？」** という考え方があります。
> 結論から言うと、**「今日だけのデータ」は統計学的にはほぼ役に立ちません！**
> 
> なぜ過去のデータを蓄積し、日付列 (`date`) で比較しなければならないのか、その決定的な理由をかみ砕いて解説します。

##### 1. 「今日だけのデータ」が統計分析で役に立たない 3 つの理由

1. **「偶然の偏り（ノイズ）」と「統計的な必然（法則）」の区別がつかない**
   たとえば、ある1日だけのデータを取ったとき、たまたま 6 号艇が 3 回も 1 着を取ったとします。今日だけのデータで見ると「6号艇は超強い！」と誤認してしまいます。
   しかし、**過去 30 日分（約 8,000 レース）** のデータを集めて比較すると、1号艇の平均勝率が約 50%〜60% で圧倒的に高く、6号艇の勝率は数%に過ぎないという **「大数の法則（Law of Large Numbers）」に基づく真の法則** が見えてきます。
2. **サンプルサイズ（データ件数）の絶対的不足**
   特定の選手（例: A1級のトップレーサー）や、特定の「モーター2連対率 40% 超えの超抜機」は、1 日の全レース中には数件しか登場しません。数件のデータで平均や傾向を計算しても、誤差（ばらつき）が大きすぎて統計的な信頼性がゼロになります。
3. **基準（ベースライン）がないため、良いか悪いかの評価ができない**
   「本日の1号艇の平均着順が 2.5 着だった」という事実だけがあっても、比較対象がなければ評価できません。**「過去 3 ヶ月間の平均が 1.8 着だったから、今日はインコースがかなり苦戦した日だった」** と比較して初めてデータに意味が生まれます。

---

##### 2. 日付列 (`date`) の役割とは？

CSV に含まれる **`date` 列（例: `2026-07-26`）** は、単なるレース開催日のメモではありません。
これは、**「過去データ（基準値）」と「本日のデータ（検証対象）」を正確にグループ分け・分離・比較するための「タイムスタンプ・インデックス」** です！

```text
  【日付列 (date) を活用した過去データ vs 当日データの比較構造】

   全蓄積データ (data/parsed_races.csv)
     ├── 過去データ群 (date < 2026-07-26) ───> 【基準値 (Baseline)】
     │                                           1号艇平均着順: 1.85着, 平均勝率: 55.4%
     │                                                      │  (比較分析)
     └── 当日データ群 (date == 2026-07-26) ───> 【検証対象 (Target)】 
                                                 本日1号艇平均着順: 2.40着 (平常時より低迷!)
```

#### 2.5 【深掘り大盛り解説】統計学における「過去データの期間」＝「量」×「品質（鮮度）」の方程式

ここで極めて重要な疑問が浮かびます。
**「過去データは『カレンダー上の期間（1ヶ月？1年？）』で測るべきか、それとも『実際のレース数（件数 $N$）』で測るべきか？」**

結論から言いましょう。ボートレース特有の事情と統計学の原則を紐解くと、**【レース数（件数 $N$）こそが統計的精度の真の支配者】** であり、本書では **「ダウンロード管理は期間（日付）、統計計算はレース数（件数 $N$）」** を本線の設計として採用します！

---

##### 1. なぜボートレースでは「期間（日数）」だけでは不十分なのか？

ボートレースには他のスポーツや株価データと異なる大きな特徴があります。それは **「全国 24 競艇場の休催日（非開催期間）・メンテナンス期間の存在」** です！

- 例えば、特定の競技場（例: 桐生）のデータ分析をしようとした際、「過去1ヶ月間」を指定しても、その月に桐生がメンテナンスや日程の都合で 1 節（約6日間）しか開催していなければ、データ件数は極めて少なくなります。
- 逆に、連続開催されていた別の場（例: 住之江）の「過去1ヶ月間」は、レース件数が数倍に膨れ上がります。

つまり、カレンダー上の「過去 1 ヶ月」という期間は、**各競艇場や選手によって手に入るデータ件数（サンプル数 $N$）が大きく変動してしまう** のです。

---

##### 2. 「期間」と「レース数」の役割分担：本書の本線設計

| 判定レイヤー | 採用する基準軸 | なぜその軸を使うのか？（統計的・実用的な理由） |
|---|---|---|
| **① データ取得・保存レイヤー**<br>(`mise.toml` タスクランナー) | **【期間（日付 `YYYYMMDD`）ベース】** | API が日付単位で配信されており、ローカルストレージへの物理保存や `curl` 取得の管理単位として最も自然で扱いやすいため。 |
| **② 統計分析・計算処理レイヤー**<br>(Racket / RacketFrames) | **【レース数（件数 $N$）ベース】** | 統計学のすべての基本公式（大数の法則・平均値の標準誤差 $SE = \sigma / \sqrt{N}$・カイ二乗検定など）は、**カレンダーの日数ではなくレース数 $N$ のみに依存する** ため。休催日の影響を完全に排除して「同じ統計的信頼度」を担保できます。 |

> [!TIP]
> ### 📖 【中盛りコラム】自然環境（天候・風）を排除し、過去データを積み重ねる統計的・相関分析上の真の意義
> 
> API データに天候や風などの自然環境要素が含まれていないことは、一見するとデメリットに感じるかもしれません。しかし、**統計学やデータサイエンスの視点から見ると、これは「本質的な本気構造（相関関係）を取り出すための大きなアドバンテージ」** に変わります！
> 
> #### 1. 天候や風は「確率的なホワイトノイズ (ランダム誤差 $\epsilon$)」である
> 毎レースの突風や偶発的な雨・波の乱れは、平均するとプラスマイナスゼロに収束する **無作為なランダムノイズ（$\epsilon_i \sim \mathcal{N}(0, \sigma^2)$）** とみなすことができます。
> 単日の数レースだけを見ていると、この風や波のノイズが影響して「1号艇が強風に煽られて敗北した」といった偶発的事象に分析結果が振り回されてしまいます。
> 
> #### 2. 過去データを積み重ねることで「ノイズが相殺消去」される！
> 過去のレースデータを $N \gg 1$（数千〜数万件）と大量に蓄積すると、ランダムな自然環境ノイズの総和は平均化され、ゼロへ収束します（$\frac{1}{N}\sum \epsilon_i \approx 0$）。
> その結果、ノイズに隠されていた **「ボートレースの真の構造的相関関係」** がクリアに浮かび上がります：
> 
> 1. **「艇番 (boat_num) vs 確定着順 (rank)」の構造的相関**: どんな風が吹こうとも、1号艇が有利である確率的アドバンテージ。
> 2. **「モーター2連対率 (motor_rate) vs 確定着順 (rank)」の機力相関**: モーター性能が高い艇ほど着順が繰り上がる絶対的相関。
> 3. **「全国勝率 (win_rate) vs 確定着順 (rank)」の選手実力相関**: A1級レーサーが上位に入着する実力相関。
> 
> **「あえて天候ノイズに惑わされず、過去データを積み重ねて本質的な相関関係を取り出す」** ――これこそが本書で実践する統計アプローチの醍醐味です！

| 取得期間の目安 | 目安レース件数 ($N$) | 「量 (件数 $N$)」の評価 | 「品質 (鮮度)」の評価 | 最適な分析用途・おすすめ活用シーン |
|---|---|---|---|---|

> ### 📖 【コラム】オープンデータ API `turnmark/api` に学ぶ構造化 JSON スキーマとデータのあり方
> 
> **1. URL構成（API エンドポイントの階層構造）の分析**
> オープンデータ API リポジトリ **[turnmark/api](https://github.com/turnmark/api)** では、ボートレースの公式データが洗練された URL 階層構造で公開・配信されています。
> * **本日の最新データ**: `https://turnmark.github.io/api/v1/today.json`
> * **日付別アーカイブデータ**: `https://turnmark.github.io/api/v1/YYYY/YYYYMMDD.json`
> 
> 年別ディレクトリ (`YYYY/`) と日付別ファイル名 (`YYYYMMDD.json`) に綺麗に整理されているため、`curl` やタスクランナーで過去の日付範囲を自動取得・累積保存するシステムをシンプルに構築できます。
> 
> **2. JSON スキーマ（構造化データ）の設計手本と Racket パース**
> `turnmark/api` の JSON は、`programs -> stadiums -> races -> racers` という直感的な階層ハッシュ構造で統一されています。
> 生 HTML のスクレイピングとは異なり、枠番（`entry_number`）、選手名（`name`）、登録番号（`number`）、級位（`rank_number_source`）、全国勝率（`national_win_rate`）、モーター2連対率（`motor_top_2_percent`）が型定義された数値・文字列として提供されており、Racket の `(require json)` を用いてそのまま RacketFrames の `DataFrame` 列（Series）へ美しく取り込める「理想的なデータ設計の手本」となっています。

## 第3章　RacketFramesによるデータ操作（データフレーム入門）

> **この章のゴール**  
> 「見慣れない難しい用語」を一切なくし、豊富な図表（アスキーアート）と日常の例えを使って、RacketFrames の仕組み（データフレーム、シリーズ、インデックス）をステップバイステップで楽しく理解する。  
> 期間ダウンロードされた累積データから、**「直近 N レース（サンプルサイズ N）」を厳密スライス抽出する集積ステップ（`df-take-recent-races`）** を習得する。  
> **使用ライブラリ**: `racketframes`

第2章で集めたボートレースのデータを、プログラムで自由自在に操作するための強力な道具 **「RacketFrames（ラケット・フレームズ）」** について、図表を交えながら超親切に解説していきます！

---

#### 3.1 そもそも「データフレーム」ってなに？

みなさんは Excel（エクセル）や Google スプレッドシートで、下のような「表」を見たことがありますよね。

```text
  【普段私たちがよく見る「表」のイメージ】

  +------+----------+----------+----------+
  | 行   | 選手名   | 全国勝率 | 艇番     |  <-- 列（項目名）
  +------+----------+----------+----------+
  | 0    | 峰竜太   |   0.85   |    1     |
  | 1    | 毒島誠   |   0.81   |    2     |
  | 2    | 瓜生正義 |   0.72   |    3     |
  +------+----------+----------+----------+
    ^
  行番号（見出し）
```

Racket の世界で、この **「縦と横に綺麗に並んだ表データ」** をそのまま扱うための仕組みが **「DataFrame（データフレーム）」** です。

Racket でデータフレームを読み込むのは、たったの 2 行で完了します。

```racket
#lang racket
(require racketframes)

;; CSVファイルを読み込んで「表（df）」を作る
(define df (read-csv "data/parsed_races.csv"))

;; 表の概要（何行・何列あるか）を画面に出す
(df-summary df)
```

> **💡 【コラム】「Excel マクロ」ではなく、なぜ R や RacketFrames なのか？**
> 
> 「Excel もマクロ（VBA）で自動化できるのでは？」と思うかもしれません。確かに自動化は可能ですが、以下の決定的な違いがあります。
> 
> 1. **一般的メリット（安全性と管理しやすさ）**: Excel マクロはセルの誤上書きやファイルの破損リスクがありますが、R や RacketFrames は元データを破壊しない「安心設計（関数型）」です。また、コードがテキストなので Git で完璧にバージョン管理できます。
> 2. **ボートレースでのメリット**: 毎日増え続ける大量のレース結果を、元のデータを汚すことなく安全・高速に集計し、いつでも正確に計算結果を再現できます！

---

#### 3.2 RacketFrames をつくる「3つの主要なパーツ」

データフレームの内部は、実は **「3つの主要パーツ」** が組み合わさってできています。

```text
+-----------------------------------------------------------------------+
|                       1. DataFrame (表全体)                           |
|                                                                       |
|  +-----------------------------------------------------------------+  |
|  |  2. Index (行の見出しタグ / 背番号)                             |  |
|  |     [ 0,  1,  2,  3,  ... ]                                     |  |
|  +-----------------------------------------------------------------+  |
|  |  3. Series (縦1列のデータグループ)                              |  |
|  |     • 列A: "racer_name" -> CSeries ["峰竜太", "毒島誠", ...]    |  |
|  |     • 列B: "win_rate"   -> NSeries [0.85, 0.81, ...]          |  |
|  |     • 列C: "boat_num"   -> ISeries [1, 2, ...]                  |  |
|  +-----------------------------------------------------------------+  |
+-----------------------------------------------------------------------+
```

1. **DataFrame（データフレーム）**: 縦と横を組み合わせた「表全体」の箱。
2. **Index（インデックス）**: 各行にペタッと貼られた「行番号の見出しタグ」。
3. **Series（シリーズ）**: 縦1列に並んだ「同じ種類のデータの束（たば）」。

この 3 つが協力することで、大量のデータを間違えずに素早く計算できます。

---

#### 3.3 Series（シリーズ）は「縦1列のデータ専門チーム」

「シリーズ（Series）」とは、表の **縦1列（縦の列）** のことです。
RacketFrames では、扱うデータの種類（文字か、整数か、小数か）に合わせて、以下の **3つの主要な専門チーム** が用意されています。

```text
  【縦1列（シリーズ）の主な種類と専門分野】

    ① ISeries（整数専門）        ② NSeries（小数・数値専門）     ③ CSeries（文字・名前専門）
   +--------------------+      +--------------------+      +--------------------+
   | 艇番 (boat_num)    |      | 全国勝率 (win_rate)|      | 選手名 (racer_name)|
   +--------------------+      +--------------------+      +--------------------+
   | 1                  |      | 0.85               |      | "峰竜太"           |
   | 2                  |      | 0.81               |      | "毒島誠"           |
   | 3                  |      | 0.72               |      | "瓜生正義"         |
   +--------------------+      +--------------------+      +--------------------+
   (Fixnum = 整数の数字)        (Flonum = 小数の数字)       (Categorical = 文字列)
```

* **`ISeries` (アイ・シリーズ)**: 1, 2, 3 のような「整数の数字」専門。
* **`NSeries` (エヌ・シリーズ)**: 0.85 や 52.4 のような「小数の数字」専門。平均値などの計算が得意！
* **`CSeries` (シー・シリーズ)**: 選手名や会場名などの「文字（名前）」専門。

この型分離により、ハイスピードな計算が可能になります。

---

#### 3.4 Index（インデックス）の秘密：図書カードと自動位置合わせ

「インデックス（Index）」は、データを探すための **「見出しタグ（図書カード）」** のような役割を持っています。

```text
  【インデックスがあるから一瞬で見つかる！】

     Index (見出しタグ)            データの行
       [ 0 ] --------------> 0行目: 峰竜太 選手
       [ 1 ] --------------> 1行目: 毒島誠 選手
       [ 2 ] --------------> 2行目: 瓜生正義 選手
```

##### 秘密①: $O(1)$ の一瞬アクセス（定数時間検索）
インデックスがあるおかげで、10万行ある巨大なデータからでも、目的の行を **瞬時（0.001秒以下）** に引っ張り出すことができます。

##### 秘密②: 自動位置合わせ（アラインメント）
もし、順番がバラバラな2つの列を足し算しようとしても、インデックスが自動的に同じタグ同士をマッチングして計算してくれます。

---

#### 3.5 データフレームのルールと注意点

データフレームを安全に扱うために、知っておくべき **「2つの大事なルール」** があります。

1. **すべての列（Series）は同じ長さで揃える！**
2. **マス（セル）を直接書き換えない！（関数型の安心設計）**

---

#### 3.6 欠損値 `RFNoData`（空欄データ）の自動スキップ

実際のデータには、データが抜け落ちている「空欄（欠損値）」が含まれることがあります。RacketFrames では空欄のことを **`RFNoData`（アールエフ・ノーデータ）** と呼び、平均値などを計算するときに自動でスキップしてくれます。

#### 3.7 🔥 【重要新ステップ】期間累積データから「直近 N レース (サンプルサイズ N)」を厳密スライス抽出する（`df-take-recent-races`）

前章で学んだ通り、**「ダウンロードは日付（期間）だが、統計の信頼性を決めるのはレース数 $N$」** でした。
各競艇場の休催日（非開催期間）によるデータの偏りを解消するため、蓄積された全 CSV データから **「直近 N レース分だけを件数基準でスライス抽出するステップ」** を導入します！

```text
  【3ステップ：期間累積 CSV から「直近 N レース」を切り出す集積構造】

   [Step 1: 期間ダウンロード] ───> 日付別JSON (data/raw/YYYYMMDD.json)
                                         │
   [Step 2: 全自動結合]       ───> 全累積CSV (data/parsed_races.csv: 例 30日分 = 8,000レース)
                                         │
   [Step 3: N件スライス]      ───> (df-take-recent-races df 1000)
                                         │
                                         ▼
                                  【厳密なサンプルサイズ N = 1,000 レース完成！】
                                  (競艇場の休催日による偏りが完全に消去される)
```

##### スライス抽出の Racket 実装ロジック (`code/ch03-racketframes-basics.rkt`)

```racket
#lang racket
(require racketframes)

;; 期間蓄積データから「直近 N レース」のみを件数基準で切り出す本線関数
(define (df-take-recent-races df n-races)
  (define rows (second df))
  (if (null? rows)
      rows
      (let ()
        ;; 1. レース一意キー (date + stadium_num + race_num) ごとにグループ化
        (define race-groups (make-hash))
        (for ([r rows])
          (define key (format "~a-~a-~a" (hash-ref r "date" "") (hash-ref r "stadium_num" 0) (hash-ref r "race_num" 0)))
          (hash-update! race-groups key (lambda (lst) (cons r lst)) '()))
        
        ;; 2. 日付・レース番号順でソート（新しい順）
        (define sorted-keys (sort (hash-keys race-groups) string>?))
        
        ;; 3. 指定の直近 N レース分だけキーを選択
        (define target-keys (take sorted-keys (min n-races (length sorted-keys))))
        
        ;; 4. 対象レースの全艇データを行リストとして結合して返す
        (apply append (map (lambda (k) (hash-ref race-groups k)) target-keys)))))
```


この `df-take-recent-races` 関数によって、どんな期間でダウンロードしたデータであっても、常に **数学的に一定のサンプルサイズ $N$** を切り出して統計計算に回すことができます！

## 第4章　RacketFramesによる統計と集計（基本統計量・フルイ・Groupby）

> **この章のゴール**  
> 平均・標準偏差の意味と計算方法を学び、データの「フルイ分け（フィルタリング）」と「箱分け一括集計（Groupby）」をマスターして、ボートレースの数理的特徴を解き明かす。  
> **使用ライブラリ**: `racketframes`

第3章で読み込んだ綺麗なデータを使って、いよいよ本格的な **「統計計算」** を行っていきます！

---

#### 4.1 🔥 【大盛り深掘り解説】なぜ「フルイ分け (フィルタリング)」と「箱分け一括集計 (Groupby)」をマスターしなければならないのか？

本章の学習に入る前に、**「なぜデータのフルイ分け（`df-filter`）と箱分け一括集計（`df-groupby`）をマスターする必要があるのか？」** その本質的な必要性と有用性を、一般的なデータサイエンスのメリットとボートレース分析の実践ストーリーの 2 つの視点から大盛りで解説します！

```text
  【生データの壁 vs フルイ分け (Filter) ＆ 箱分け (Groupby) の威力】

   [巨大な生データ (Raw Data)] ───> 【平均の罠！】全体平均だけ出しても何も見えない...
  (何万行もの混ざり合った表)                   │
                                               ├─> ① フルイ分け (Filter) : ノイズ除去 ＆ 特定条件の隔離抽出
                                               │
                                               └─> ② 箱分け (Groupby)  : カテゴリごとの構造的格差が一目瞭然！
```

---

##### 1. 一般的なデータ分析・ビジネスにおける必要性と有用性（一般的メリット）

ビジネスやデータサイエンスの現場において、生のデータ（Raw Data）をそのまま眺めたり、全体の平均値だけを計算したりすることには **大きな罠（平均の罠）** が潜んでいます。

1. **「情報過多のノイズ」を削ぎ落とす必要性**
   何万行・何十万行ものデータには、欠損値（空欄）や分析対象外の無効なデータが含まれています。フィルタリング（フルイ分け）を使わずに全体を集計すると、ノイズデータに数値が引きずられ、誤った結論を導いてしまいます。
2. **「平均の罠」を回避し、ターゲットを隔離分析（アイソレーション）する有用性**
   例えば、あるECサイトの「全顧客の平均購入額」を計算して $3,000$ 円だったとします。しかし、実際には「月1回以上購入する優良顧客（平均 $15,000$ 円）」と「初回のみの非アクティブ顧客（平均 $500$ 円）」に分かれていた場合、全体平均の $3,000$ 円は何のマーケティング施策にも役立ちません。
   `df-filter` で特定の顧客層や条件だけをすくい取ることで、**ターゲットごとの真の挙動を明確に把握（アイソレーション分析）** できます。
3. **手作業をゼロにし、カテゴリごとの構造比較を自動化する圧倒的有用性**
   Excel やスプレッドシートで「国別」「店舗別」「商品カテゴリ別」に集計しようとすると、フィルターを手動で切り替えてコピペ計算を何度も繰り返さなければならず、時間もかかり打ち間違いのリスクも高まります。
   `df-groupby`（箱分け集計）をマスターすると、**「データをカテゴリごとの箱に自動分類し、1行のコードで全グループの平均・合計・分散を一括計算」** できます。分析のスピードと再現性が劇的に向上します！

---

##### 2. ボートレースデータ分析における具体的な必要性と有用性（ステップバイステップ実践解説）

ボートレースのデータ分析においては、この「フルイ分け」と「箱分け集計」が **絶対になくてはならない決定的な武器** になります。

なぜなら、ボートレースのデータには **「1号艇〜6号艇の枠番」「A1級〜B2級の選手級位」「モーター2連対率」「24箇所の競艇場」という強烈なカテゴリ属性** が最初から組み込まれているからです！

> [!IMPORTANT]
> ### 🚀 【ステップバイステップ】ボートレース分析における 4 つの必須実践ストーリー
> 
> - **ステップ 1: 【ノイズとフライング等の排除】 (`df-drop-na` / `df-filter`)**
>   - フライング（F）や返還欠場で成績データが途切れている不完全な行を自動除去します。完全に揃ったデータだけを分析対象にすることで、統計的比較の公認ルールを確立します。
> 
> - **ステップ 2: 【注目条件の分離・フルイ抽出】 (`df-filter`)**
>   - 「1号艇（インコース）のデータだけ」「勝率 0.75 以上の A1 級エリート選手だけ」「モーター2連対率 40% 超えのエース機だけ」をフルイにかけます。特定条件を満たすレーサーの平均着順や連対率を単独で精密測定できます。
> 
> - **ステップ 3: 【カテゴリー別の箱分け一括比較】 (`df-groupby`)**
>   - 全レースデータを「1枠の箱」「2枠の箱」……「6枠の箱」へと一斉に箱分けします。`df-groupby` を適用することで、たった 1 行で 1枠〜6枠それぞれの「平均確定着順」と「平均勝率」が並んだ比較表が完成します。
> 
> - **ステップ 4: 【数値による客観的証明とモデルへの昇華】**
>   - 単に「1号艇が有利らしい」という漠然としたイメージではなく、「1号艇の平均着順は 1.85 着、6号艇は 4.85 着」という **圧倒的な数理的格差（構造的アドバンテージ）** を客観的に証明できます。この数値が、第5章の散布図プロットや第6章の予想スコアモデルの重み付け算出における「揺るぎない根拠」となります！

---

#### 4.2 🔥 【大盛り深掘り解説】基本統計量：平均値 (`df-mean`) と標準偏差 (`df-std`) を学ばなければいけない理由とメリット

続いて、データの二大基本指標である **「平均値 (`df-mean`)」** と **「標準偏差 (`df-std`)」** について、なぜこの 2 つをセットで学ばなければならないのか、その理由とメリットを深掘り解説します！

```text
  【平均値だけ vs 平均値 ＋ 標準偏差の組み合わせ比較】

   [平均値だけを見る世界] ───> 「選手Aも選手Bも平均着順 3.0着だから、同じ強さ！」(大きな誤解!)
                                              │
                                              ▼ (標準偏差 std を追加計測)
   [平均 ＋ 標準偏差の世界] ───> 選手A: std小 (2〜3着に固まる極めて安定した実力派)
                                  選手B: std大 (1着か6着かの極端なピンロク波乱型キーマン!)
```

##### 1. なぜ平均値と標準偏差をセットで学ぶのか？（一般的理由とメリット）

1. **平均値 (`df-mean`) の役割と限界：データの「中心（代表値）」を一言で表す**
   何千件ものデータを 1 つの数で表す代表値が「平均値」です。しかし、**平均値だけを見ることは非常に危険** です。
   たとえば、全員が $50$ 点のクラス A と、$100$ 点と $0$ 点が半分ずつのクラス B は、どちらも「平均 $50$ 点」になります。平均値だけではデータの実態（リスクやばらつき）を見抜けません。
2. **標準偏差 (`df-std`) の役割：データの「ブレ（リスク・安定性）」を定量化する**
   この「データの散らばり具合（ばらつき）」を数式でぴったり数値化したものが **標準偏差（Standard Deviation / $\sigma$）** です。
   - **標準偏差が小さい**: データが平均値のまわりにキュッと集まっており、**「ブレが少なく安定している（再現性が高い）」** ことを意味します。
   - **標準偏差が大きい**: データが上下に激しく散らばっており、**「ブレが大きく波乱要素が高い（リスクが高い）」** ことを意味します。
3. **一般的なメリット**
   意思決定において「期待できる成果（平均値）」だけでなく「ブレやリスクの大きさ（標準偏差）」を同時に評価できるようになり、投資・品質管理・マーケティングにおいて **リスク管理された信頼度の高い意思決定** が可能になります。

---

##### 2. ボートレース統計の観点における具体的な必要性とメリット

ボートレースのデータ分析において、平均値と標準偏差を組み合わせることは **勝ち筋（本命か穴か）を見極める最強の眼** になります！

##### ① 選手の実力タイプ分析：「安定型レーサー」vs「ピンロク波乱型レーサー」の見抜き方
同じ「平均確定着順 3.0 着」の 2 人の選手がいたとします：
- **選手 A (標準偏差が小さい / $\sigma \approx 0.8$)**:
  どのレースでも確実に 2 着〜3 着に入着する **「極めて安定した実力派」**。2連複や3連複の軸として最も信頼できます。
- **選手 B (標準偏差が大きい / $\sigma \approx 2.1$)**:
  1 着を取るか、失敗して 6 着に沈むかの極端な **「ピンロク（1か6か）波乱型レーサー」**。頭（1着固定）で買うか、消すかの極端な予想が有効となり、万舟券（高配当）を生み出すキーマンになります。

##### ② モーター性能の節目評価：節ごとの「機力格差」を見抜く
各競艇場の節（開催期間）ごとにモーター2連対率の標準偏差を計算します。
- **モーター2連対率の標準偏差が小さい節**: 全ボートのエンジン性能が均一であり、「枠番や選手の実力で決まる堅いレース展開」になると判定できます。
- **モーター2連対率の標準偏差が大きい節**: 一部の超抜エース機とポンコツ機に圧倒的な性能差が開いており、「アウトコースからでもエース機が捲り切る大波乱レース」が多発すると事前に見抜けます！

#### 4.5 グループ化と集約 (`df-groupby`)：箱分けして一括集計

データ分析の中で一番パワフルなのが **`df-groupby`（グループバイ）** です。
データを枠番（1枠〜6枠）ごとに「箱分け」して、それぞれの箱の中で平均値を一発で計算してくれます。

```text
  【df-groupby はデータを箱分けして一斉に集計する】

                        ┌───> [1号艇の箱] ───> 平均着順: 1.85着
                        │
    [全データ] ──Groupby──┼───> [2号艇の箱] ───> 平均着順: 2.80着
   (boat_numで分類)     │
                        ├───> [3号艇の箱] ───> 平均着順: 3.40着 ...
                        │     ...
                        └───> [6号艇の箱] ───> 平均着順: 4.85着
```

```racket
;; boat_num (枠番) ごとにグループ化し、着順(rank) と 勝率(win_rate) の平均を集計
(define df-boat-summary
  (df-groupby df "boat_num"
              '(("rank" . mean)
                ("win_rate" . mean))))

;; 集計結果をきれいに表示
(df-show df-boat-summary)
```

実行結果のイメージ：

| boat_num (枠番) | rank_mean (平均着順) | win_rate_mean (平均勝率) |
| :--- | :--- | :--- |
| **1** | **1.85** | **0.68** |
| **2** | **2.80** | **0.55** |
| **3** | **3.40** | **0.50** |
| **4** | **3.85** | **0.46** |
| **5** | **4.20** | **0.42** |
| **6** | **4.85** | **0.38** |

この結果を見ると、**「1号艇がダントツで有利で、外枠に行くほど平均着順が悪くなる」** というボートレースの重要な特徴が、数値としてはっきり証明されます！

##### 1. 用語の背景情報：なぜ「散布図（Scatter Plot）」が必要になったのか？
19世紀の統計学者フランシス・ゴルトンらが「2つの数値変数の間にどのような関連性（相関）があるか」を研究する中で考案されたのが **散布図（Scatter Plot）** です。
数値の並んだ表データ（何千行もの CSV）を見ただけでは、人間の脳は数値同士の関係性を認識できません。横軸（X軸）と縦軸（Y軸）の2次元平面上にデータを「点」として打ち込むことで、データの関係性を直感的な「形」として捉えるために散布図が発明されました。

##### 2. なぜ学ぶ必要があるのか？ ＆ 一般的メリット（大盛り解説）
1. **「文字と数値の壁」を超え、0.1秒でパターンを捉える圧倒的認知メリット**
   人間の視覚処理脳（後頭葉）は、文字や数字の解読（左脳言語野）よりも、二次元平面上のパターンの認識を数千倍速く処理できます。巨大な表データをグラフにするだけで、データ全体の傾向・傾き・固まり（クラスタ）を瞬時に把握できます。

#### 6.1 予想モデルの数理設計

##### 3. ボートレースデータ分析における具体的な関係（中盛り解説）
ボートレースにおける各艇の強さを表す **予想スコア ($Score$)** を、以下の 3 要素を統合した数式でモデル化します。

$$Score = (\text{枠番アドバンテージ点}) + (\text{全国勝率} \times 50) + (\text{モーター2連対率} \times 30)$$

##### 枠番アドバンテージ点の重み設計
- 1号艇: 40点（第4章で証明した1号艇の圧倒的平均着順優位性を加点）
- 2号艇: 25点 / 3号艇: 15点 / 4号艇: 10点 / 5号艇: 5点 / 6号艇: 0点

#### 6.2 テーブルの結合 (`df-join`)：出走表と過去成績のガッチャンコ

##### 1. 用語の背景情報：なぜ「テーブルの結合 (`df-join`)」が必要なのか？
リレーショナルデータベース（RDB）やデータフレーム操作において、バラバラに管理されている複数のテーブルを共通のキー（主キー・外部キー）で接続する処理が **結合（Join）** です。
データ分析の現場では、「本日のイベントデータ（出走表）」と「過去の蓄積データベース（選手成績）」が別々のファイルとして存在するため、これらを 1 つの表に結合する技術が不可欠になりました。

##### 2. なぜ学ぶ必要があるのか？ ＆ 一般的メリット（大盛り解説）
1. **不足している情報を別データソースから瞬時に参照・補完する**
   「本日の出走表」には当日の枠番しか載っていない場合でも、「過去データベース」から選手ごとの過去通算勝率やモーター連対率を結合して一瞬で能力値を補完できます。
2. **手作業によるミスや照合の手間をゼロにする**
   Excel で手作業で探したり VLOOKUP 関数を組む手間をなくし、`df-join` 一行で何万行ものデータをキー（`racer_id` 等）に基づいてミスなく完璧に照合・結合できます。

##### 3. ボートレースデータ分析における具体的な関係（中盛り解説）
本日の出走表データ（`df-today`）に、第2章で蓄積した過去データ（`df-history`）から算出した「過去勝率」や「モーター2連対率」を `racer_id` をキーにして `df-join`（テーブル結合）でガッチャンコ結合します！

```racket
#lang racket
(require racketframes)

(define df-today (read-csv "data/parsed_races.csv"))
(define df-history (read-csv "data/parsed_races.csv"))

;; racer_id をキーにして出走表と過去成績データをガッチャンコ結合
(define df-merged (df-join df-today df-history "racer_id"))
```

#### 6.3 予想スコアの全自動計算

##### 1. 背景情報と学ぶメリット（大盛り解説）
プログラム上で定義した関数をデータフレームの全行に対して一括適用するバッチ計算技術です。人間が電卓を叩くことなく、1 秒で全レース全ボートの予想スコアを自動計算します。

##### 2. ボートレースデータ分析における具体的な関係（中盛り解説）
結合したデータに対して、6.1 で設計した数式を適用し全艇のスコアを一括計算します。

```racket
(define (calc-boat-score row)
  (define b-num (hash-ref row "boat_num"))
  (define w-rate (hash-ref row "win_rate"))
  (define m-rate (hash-ref row "motor_rate"))
  
  (define course-score
    (cond [(= b-num 1) 40.0] [(= b-num 2) 25.0] [(= b-num 3) 15.0]
          [(= b-num 4) 10.0] [(= b-num 5) 5.0]  [else 0.0]))
  
  (+ course-score (* w-rate 50.0) (* m-rate 30.0)))
```

#### 6.4 予測の検証：実際の結果と答え合わせをしよう！ (`evaluate-model`)

##### 1. 用語の背景情報：なぜ「予測の検証（Model Evaluation / Backtesting）」が必要なのか？
データサイエンスや金融工学・AI開発において、作成したモデルが実際にどれくらいの精度を持つかを過去の「答え（確定着順）」と照らし合わせて判定するプロセスが **モデル検証（Evaluation / バックテスト）** です。
モデルを作っただけで満足するのではなく、実際の的中率を数値化して客観的に採点する品質管理手法として生まれた背景があります。

##### 2. なぜ学ぶ必要があるのか？ ＆ 一般的メリット（大盛り解説）
1. **モデルの「自己満足」を防ぎ、実際の運用可能性を評価する**
   「完璧に思える数式」であっても、実際にテストすると的中率が低い場合があります。客観的な的中率（%）を算出することで、モデルの真の実力を評価できます。
2. **チューニングと改善のループを回す基準ができる**
   的中率が 55% だった場合、「勝率の配分を少し上げてみよう」といった試行錯誤の目標値が得られます。

##### 3. ボートレースデータ分析における具体的な関係（中盛り解説）
算出された全艇の予想スコアの中で **最高スコアを獲得した本命艇** が、実際のレース結果で本当に 1 着（`rank = 1`）になったか否かを答え合わせテストします！

```racket
;; 予想1位の艇が、実際のレースで何%の確率で1着(rank = 1)になったか計算
(define (evaluate-model df-pred)
  (define df-top-score (df-groupby-max df-pred "race_id" "score"))
  (define correct-count
    (df-count (df-filter df-top-score (lambda (row) (= (hash-ref row "rank") 1)))))
  (define total-races (length (df-unique df-pred "race_id")))
  
  (printf "検証したレース数: ~a\n" total-races)
  (printf "1着的中数: ~a\n" correct-count)
  (printf "予測的中率: ~a%\n" (* (/ correct-count total-races) 100.0)))

(evaluate-model df-predicted)
```

## 付録B　主要用語集（Glossary）

> **この付録のゴール**  
> 本書に登場する「RacketFrames/データ構造用語」「統計用語」「ボートレース用語」の3分野の概念と関係性を辞書形式で一覧参照できるようにする。  

---

#### B.1 RacketFrames・データ構造用語

* **DataFrame（データフレーム）**
  * 共通の `Index` を共有し、複数の `Series`（列）を束ねた2次元の表構造体。
* **Series（シリーズ）**
  * データフレームの1つの列に相当する1次元の型付き配列。
* **`ISeries` (Integer Series)**
  * 整数型（艇番や登録番号など）に最適化されたシリーズ。
* **`NSeries` (Numeric/Float Series)**
  * 実数型（勝率やタイムなど）の高速演算用シリーズ。
* **`CSeries` (Categorical Series)**
  * 選手名や会場名などの文字・シンボル列用シリーズ。
* **`BSeries` (Boolean Series)**
  * 真偽値 (`#t`/`#f`) を保持するフラグ用シリーズ。
* **Index（インデックス）**
  * 各行を識別するハッシュ構造キー（`SIndex`, `IIndex` など）。$O(1)$ の高速検索と自働アラインメントを提供。
* **`RFNoData`**
  * RacketFrames における欠損値（空欄データ）を表す特別なオブジェクト。
* **`iloc` / `loc`**
  * `iloc` は行番号（位置）によるアクセス、`loc` はインデックス名（ラベル）によるアクセス。
* **アラインメント (Alignment)**
  * 異なる順序や長さの Series 演算時に、Index キーを照合して自動的に位置を合わせる機能。

---

#### B.2 統計・分析用語

* **平均値 (Mean / `df-mean`)**
  * データの合計をデータの個数で割った代表値。
* **標準偏差 (Standard Deviation / `df-std`)**
  * データが平均値の周りにどれくらい散らばっているかを示す指標。
* **分散 (Variance)**
  * 偏差の2乗の平均値。データのばらつき度合い。
* **フィルタリング (Filtering / `df-filter`)**
  * 特定の条件を満たす行だけを抜き出す操作。
* **グループ化と集約 (Groupby & Aggregation / `df-groupby`)**
  * 枠番別や会場別などのカテゴリごとにデータを分類し、統計量をまとめる操作。
* **散布図 (Scatter Plot / `df-plot-scatter`)**
  * 2つの変数の相関関係を平面上の点として視覚化したグラフ。
* **ヒストグラム (Histogram / `df-plot-histogram`)**
  * データの分布状態を度数に応じた柱状グラフで表示したもの。

---

#### B.3 ボートレース（競艇）ドメイン用語

* **艇番 (1号艇〜6号艇)**
  * レースに出走する6艇の識別番号。内側から1号艇（白）、2号艇（黒）、3号艇（赤）、4号艇（青）、5号艇（黄）、6号艇（緑）。
* **全国勝率 (ぜんこくしょうりつ)**
  * レーサーが過去6ヶ月間で獲得した着順点の平均。実力を示す重要指標。
* **2連対率 (にれんたいりつ)**
  * 2着以内に入った割合。特にモーター性能の良し悪しを示す指標として重視される。
* **フライング (F)**
  * 大時計が0秒になるより早くスタートラインを通過してしまう反則。即座に失格・返還欠場となる。
* **出遅れ (L)**
  * 大時計が0秒になってから1秒以上遅れてスタートラインを通過する反則失格。
* **枠なり進入 (わくなりしんにゅう)**
  * 艇番通りのコース割り（1号艇が1コース）でスタートすること。
* **深イン (ふかいん)**
  * 内コースを強引に奪った結果、助走距離が短くなってしまう状態。
* **2連単 / 3連単**
  * 1着・2着（3着）を順番通りに当てる人気の舟券（3連単の平均配当は約7,000〜8,000円）。

#### C.1 エラーメッセージの読み方

Racket でエラーが発生した際、DrRacket の相互作用ウィンドウ（下段）に赤字でメッセージが表示されます。エラーメッセージは**「最後の行」から逆順に読む**のがコツです。

##### よくあるエラーメッセージと対処法

1. **`read-syntax: expected a ')' to close '('`**
   * **原因**: 閉じ括弧 `)` が足りません。
   * **対処**: 括弧のペアを確認します。DrRacket で括弧の上にカーソルを置くと、対応する括弧がグレーでハイライトされます。
2. **`unbound identifier: win-rate`**
   * **原因**: `win-rate` という名前の変数や関数が定義されていません（スペルミスや、Run ボタンを押し忘れている状態）。
   * **対処**: つづりを確認するか、上部の **Run** ボタンを押してプログラムを再読み込みしてください。
3. **`contract violation: expected <number?>, given <string?>`**
   * **原因**: 数値が必要な計算（例： `+` や `df-mean`）に、誤って文字列データが渡されています。
   * **対処**: データフレームの列のデータ型（`ISeries`/`NSeries` か `CSeries` か）を確認してください。

#### C.2 相互作用ウィンドウ（REPL）での対話的トラブルシューティング

## 付録E　curl を使ったデータ収集とコマンドガイド

> **この付録のゴール**  
> コマンドラインでデータや Web ページを取得・保存する万能ツール **`curl`（カール）** の基本概念・各 OS でのインストール方法・サーバー負荷を下げるスリープ（ウェイト）オプション・オープンデータ API (`turnmark/api`) や生データ (HTML) の取得手法・および本書で使うボートレースデータ取得スクリプトの全オプションの意味を丁寧に理解する。  

---

#### E.1 `curl`（カール）とは？

**`curl`（Client URL / カール）** は、インターネット上のサーバーと通信し、データのダウンロードやアップロードをターミナル（コマンドライン）から行うための世界標準のデータ収集ツールです。

ウェブブラウザ（Chrome や Edge）が「マウスでページを表示するツール」だとすれば、`curl` は **「プログラムやコマンドから直接データを手元に引き寄せるツール」** です。

```text
  【ウェブブラウザ vs curl コマンドのイメージ】

   [ウェブブラウザ] ──> マウスで画面を見る (人間用)
   [curl コマンド]  ──> ターミナルから一瞬でファイルを保存 (データ分析・プログラム用)
```

---

#### E.2 💡 構造化データ API (`turnmark/api`) と公式 Web (HTML) の二大取得経路

本書では、以下の 2 つのデータ取得経路で `curl` を活用しています。

1. **【本線】オープンデータ API (`turnmark/api`)**:
   `https://turnmark.github.io/api/v1/today.json` や `https://turnmark.github.io/api/v1/YYYY/YYYYMMDD.json` から構造化 JSON データを直接 `curl` で高速取得・保存。
2. **【参考・応用】公式 Web サイト (HTML 生データ)**:
   `boatrace.jp` から人間用の HTML 出走表を `curl` 取得し、Racket 正規表現でパース（`pyjpboatrace` 流）。

```text
  【データサイエンスのパイプライン】

   [オープンデータ API (turnmark/api)] ──curl──> 日付別JSON (20260726.json)
                                                       │
                                                       ▼ (require json) で自動スキャン
   [RacketFrames で分析!] <── 累積CSV <── 構造化データ (parsed_races.csv)
```

#### E.3 OS 別の `curl` インストール方法

`curl` は多くの OS（macOS や Windows 10/11）に最初から標準搭載されていますが、インストールされていない場合のセットアップ手順は以下のとおりです。

##### 1. Linux (Ubuntu / Debian / Linux Mint)
ターミナルで以下の 2 行を実行します。

```bash
sudo apt update
sudo apt install -y curl
```

##### 2. macOS
macOS には最初から `curl` が組み込まれています。特別なインストール作業は不要です。

##### 3. Windows (Windows 10 / 11)
Windows 10（1803以降）および Windows 11 の「コマンドプロンプト」または「PowerShell」には、標準で `curl.exe` が入っています。ターミナルを開いて `curl --version` と打つだけでそのまま利用できます。

#### E.4 基本的な `curl` コマンドスクリプト一覧

よく使われる `curl` の代表的なコマンドパターンを紹介します。

```text
  +-----------------------------------------------------------------------------------+
  |               🛠️ よく使う `curl` コマンドの代表パターン一覧                      |
  +-----------------------------------------------------------------------------------+
  | ① curl URL                     : Web ページの内容を画面にそのまま表示する          |
  | ② curl -o filename URL         : 指定したファイル名で保存する                     |
  | ③ curl -O URL                  : サーバー上のファイル名と同じ名前で保存する        |
  | ④ curl -s -o filename URL      : 進捗メーターを出さずに静かに保存する (Silent)    |
  | ⑤ curl --limit-rate 100k URL   : 通信帯域を制限してサーバー負荷を下げる            |
  | ⑥ curl --rate 1/s URL (新)     : リクエストのアクセス頻度を1秒間に1回以下に抑える  |
  +-----------------------------------------------------------------------------------+
```

---

#### E.5 🛡️ 【絶対必須ルール】サーバー負荷を下げるスリープ（アクセス待ち時間）オプション

複数の Web ページや過去のレースデータを連続して取得する場合、**「相手のサーバーに負荷をかけないためのアクセススリープ（ウェイト時間）」を挟むことが倫理的・技術的に絶対必須のルール** です。

```text
  【スリープ（ウェイト）なし vs スリープありの比較】

   [危険な連続アクセス] ──> リクエスト ─> リクエスト ─> リクエスト ──> (サーバー障害・アクセス拒否！)
                                                                          
   [安全なアクセス]     ──> リクエスト ─> [ sleep 1秒 ] ─> リクエスト ──> (サーバーに優しく安全！😊)
```

##### 1. スクリプト内での `sleep 1`（または `sleep 2`）の挿入
連続して `turnmark/api` や公式 Web からデータを取得する際は、必ず 1 回の `curl` ごとに `sleep 1`（1秒間の待ち時間）を挿入します。

```bash
# 過去期間の JSON データを安全に一括ダウンロードする例
for date in 20260701 20260702 20260703; do
  echo "Downloading $date.json..."
  curl -s --limit-rate 100k -o "data/raw/${date}.json" "https://turnmark.github.io/api/v1/2026/${date}.json"
  sleep 1
done
```

#### E.6 本書で使うボートレースデータダウンロード・スクリプトの徹底解説

##### 1. `turnmark/api` 日付指定 JSON の安全なダウンロード
```bash
curl -s --limit-rate 100k -o data/raw/20260726.json "https://turnmark.github.io/api/v1/2026/20260726.json"
```

##### 2. ボートレース公式Webサイトの出走表 (HTML) の安全なダウンロード
```bash
curl -s --limit-rate 100k -o data/raw/racelist_sample.html "https://www.boatrace.jp/owpc/pc/race/racelist?rno=1&jcd=01&hd=20260725"
sleep 1
```

##### 💡 コマンドのオプション解説
* **`-s` (Silent)**: 進捗バーを出さず静かにダウンロード。
* **`--limit-rate 100k`**: 通信スピードを最大 100KB/s に制限。
* **`-o` (Output)**: 保存先ファイルパスを指定。
* **`sleep 1`**: 連続アクセス時のサーバー保護ウェイト。

* **【主張 (Claim)】**: `curl` コマンドに速度制限とスリープを付与することで、`turnmark/api` 等から安全・持続可能にレースデータを自動収集できる。
* **【事実・データ (Fact)】**: `--limit-rate 100k` オプション、`-o` による出力指定、および `sleep 1` を組み込んだ shell スクリプト（`mise.toml`）。
