> **この章のゴール**  
> Webや外部ツール（`curl`）およびオープンAPI（`boatraceopenapi`）を活用してボートレースのデータ（JSON/HTML）を手元に取得し、プログラムで扱える構造化CSVへと変換する。  
> **【本線】**: `boatraceopenapi` から用途に合わせたタスクランナーメニュー（`today`, `json`, `range`）で日付別 JSON (`data/raw/YYYYMMDD.json`) を取得・蓄積保存し、Racket 標準の `(require json)` で全自動スキャン＆蓄積パース（`code/ch02-json-parser.rkt`）。  
> **【参考・応用】**: 公式Webサイト（HTML生データ）の `curl` 取得と正規表現パース（`code/ch02-html-parser.rkt`）。  
> **使用技術**: Racket `net/url`, `json`, `curl`, `mise` タスクランナー (`mise run data:download:today`, `mise run parse:json`, `mise run parse:html`)

本章では、統計分析の土台となる「データ収集」の手法を学びます。現在ではボートレースのデータをオープンデータとして JSON 形式で配信する **`boatraceopenapi/api`** が存在するため、本章では **「用途に応じたダウンロードタスクで JSON データを手元に蓄積保存し、Racket で一括パースする手法」を本線** として解説します。

また、従来手法や他言語ライブラリ（`pyjpboatrace` 等）でよく行われている **「公式Webサイトから HTML 生データをダウンロードしてパースする手法」** も発展学習として併せて解説します。

> [!NOTE]
> **⚠️ 【第1章に続き再確認】自然環境要素（天候・風向・風速・波高など）の扱いについて**  
> 第1章でも触れた通り、`boatraceopenapi` を含む標準的なデータ API には天候（晴れ・雨）、風向・風速、波高、水温などの【自然環境要素】は含まれておりません。そのため、**本書ではこれら天候や風などの自然環境要素はモデルに含めずスコープ外として扱い**、艇番・選手成績・モーター2連対率・確定着順といった **構造的データに特化して分析を進めます。**

#### 2.1 【本線】オープンデータ API から日付指定・期間一括 JSON を取得・蓄積してパースする

最もしっくりかつ確実なデータ収集法は、すでに構造化されて提供されている **JSON データ API** を活用することです。

##### 1. `boatraceopenapi/api` と目的別タスクランナーメニュー
[boatraceopenapi/api](https://github.com/boatraceopenapi/api) では、日付ごとのレースデータ（出走表・直前情報・確定着順）が以下の URL で配信されています。

- **本日のデータ**: `https://boatraceopenapi.github.io/api/v1/today.json`
- **日付指定データ（2026年01月01日以降）**: `https://boatraceopenapi.github.io/api/v1/YYYY/YYYYMMDD.json`

本書のリポジトリでは、用途や学習段階に応じて使い分けられる **4 種類のデータダウンロードメニュー（タスクランナー）** を用意しています。

| タスクコマンド | 用途・機能概要 | 日付指定プロンプト | 保存ファイル名 |
|---|---|---|---|
| **`mise run data:download:today`** (または `data:download`) | **【本日即時取得】** 日付確認なしで本日のデータのみを一発で全自動ダウンロード | なし（即時実行） | `data/raw/YYYYMMDD.json` |
| **`mise run data:download:json`** | **【単日対話指定】** プロンプトで日付を確認・選択（指定の過去日にも変更可） | あり（デフォルト: 本日） | `data/raw/YYYYMMDD.json` |
| **`mise run data:download:range`** | **【過去期間一括】** 開始日と終了日を指定して過去複数日分を一括ダウンロード蓄積 | あり（開始日〜終了日） | `data/raw/YYYYMMDD.json` |
| **`mise run data:download:official`** | **【HTML参考】** ボートレース公式Webサイトから 1 レース分の HTML を取得 | なし（桐生1R固定） | `data/raw/racelist_sample.html` |

##### 2. ダウンロードタスクランナーの具体的な使い方

###### ① 本日分のみをサクッと一発取得したいとき (`mise run data:download:today`)
日付の入力や確認画面を出さず、「とにかく今日のボートレースデータを取得したい」場合に最適です。

```bash
# 本日分のレースデータを無確認で一発取得
mise run data:download:today
```

```text
本日のボートレースデータ (20260726) を自動ダウンロードしています...
ダウンロード完了: data/raw/20260726.json
```

###### ② 特定の過去日を指定して取得したいとき (`mise run data:download:json`)
対話プロンプトが表示され、日付を入力・変更できます（そのまま Enter で本日分）。

```bash
# 日付を確認・指定して単日データ取得
mise run data:download:json
```

```text
取得対象の日付を入力してください (YYYYMMDD) [デフォルト: 20260726]: 20260501
ボートレースデータ (対象日: 20260501) をダウンロードしています...
ダウンロード完了: data/raw/20260501.json
```

###### ③ 過去数日〜数ヶ月分のデータを一括蓄積したいとき (`mise run data:download:range`)
開始日と終了日を指定し、まとめデータを順次ローカルフォルダ `data/raw/` に蓄積します。

```bash
# 過去の期間を一括指定して連続ダウンロード
mise run data:download:range
```

```text
==========================================================
 期間指定ダウンロード開始: 20260701 〜 20260705
==========================================================
[20260701] 取得中... 成功 -> data/raw/20260701.json
[20260702] 取得中... 成功 -> data/raw/20260702.json
...
期間指定ダウンロードが完了しました！
```

##### 3. Racket による全 JSON ファイルの自動スキャン & 蓄積パース（`code/ch02-json-parser.rkt`）
Racket の標準ライブラリ `(require json)` を使い、`data/raw/` ディレクトリ配下に蓄積されたすべての `*.json` ファイルを自動検出して順次パースし、単一の構造化 CSV (`data/parsed_races.csv`) へと集約結合します。

付属ソースコード [code/ch02-json-parser.rkt](file:///home/mevius/my-project/mypublish-racket-statistics/code/ch02-json-parser.rkt) の主要ロジックは以下の通りです。

```racket
#lang racket
(require json)

;; 1. data/raw 配下の全 *.json ファイル（過去の日付分含む）を全自動検出
(define target-files
  (filter (lambda (p) (string-suffix? (path->string p) ".json"))
          (directory-list "data/raw" #:build? #t)))

;; 2. 各 JSON ファイルの programs -> stadiums -> races -> racers を走査し結合
;; (累積データとして CSV data/parsed_races.csv へ書き出し)
```

実行は以下のコマンド一発です：

```bash
# 【本線】Racket による全 JSON スキャン & CSV 蓄積パースの実行
mise run parse:json
```

日々タスクランナーでデータを取得・更新し `mise run parse:json` を動かすことで、分析用の過去レースデータが CSV にどんどん蓄積されていきます！

#### 2.3 💡 生データ (HTML) と構造化データ (JSON/CSV) のパイプライン比較

データ分析における 2 つのアプローチの違いを整理しましょう。

```text
  【本線パイプライン (目的別ダウンロード ＆ 日付別 JSON 蓄積)】
   [データダウンロードメニュー] ───> [boatraceopenapi API] ─── curl ───> 日付別JSON (data/raw/YYYYMMDD.json)
                                                                             │
                                                                             ▼ (require json) で全自動スキャン
   RacketFrames で分析! <─── 累積CSV <─── 構造化データ (data/parsed_races.csv)

  【従来/応用パイプライン (HTML スクレイピング)】
   [ボートレース公式Web] ─── curl ───> 生HTML (racelist.html)
                                              │
                                              ▼ 正規表現 / HTMLパース
   RacketFrames で分析! <─── CSV保存 <─── 構造化データ (data/parsed_races.csv)
```

1. **構造化 JSON 日付別保存 (本線)**: 当日一括、単日対話指定、過去期間一括を選択でき、日々のデータが別名ファイルで蓄積されるため、上書きリスクゼロで安定して時系列分析用データセットを拡張できます。
2. **生データ HTML (参考/応用)**: Web ページの装飾が含まれた人間用データ。タグ構造が変わるとパースが壊れやすいため、API が存在しない場合の最終手段として役立ちます。

> [!IMPORTANT]
> ### 🔥 【統計学の真髄】なぜ「今日だけのデータ」では役に立たないのか？ ＆ 日付列 (`date`) の重要性
> 
> 初学者がよく陥る罠として、**「今日のレース結果だけダウンロードすれば、分析や予想ができるのでは？」** という考え方があります。
> 結論から言うと、**「今日だけのデータ」は統計学的にはほぼ役に立ちません！**
> 
> なぜ過去のデータを蓄積し、日付列 (`date`) で比較しなければならないのか、その決定的な理由をかみ砕いて解説します。

##### 1. 「今日だけのデータ」が統計分析で役に立たない 3 つの理由

1. **「偶然の偏り（ノイズ）」と「統計的な必然（法則）」の区別がつかない**
   たとえば、ある1日だけのデータを取ったとき、たまたま 6 号艇が 3 回も 1 着を取ったとします。今日だけのデータで見ると「6号艇は超強い！」と誤認してしまいます。
   しかし、**過去 30 日分（約 8,000 レース）** のデータを集めて比較すると、1号艇の平均勝率が約 50%〜60% で圧倒的に高く、6号艇の勝率は数%に過ぎないという **「大数の法則（Law of Large Numbers）」に基づく真の法則** が見えてきます。
2. **サンプルサイズ（データ件数）の絶対的不足**
   特定の選手（例: A1級のトップレーサー）や、特定の「モーター2連対率 40% 超えの超抜機」は、1 日の全レース中には数件しか登場しません。数件のデータで平均や傾向を計算しても、誤差（ばらつき）が大きすぎて統計的な信頼性がゼロになります。
3. **基準（ベースライン）がないため、良いか悪いかの評価ができない**
   「本日の1号艇の平均着順が 2.5 着だった」という事実だけがあっても、比較対象がなければ評価できません。**「過去 3 ヶ月間の平均が 1.8 着だったから、今日はインコースがかなり苦戦した日だった」** と比較して初めてデータに意味が生まれます。

---

##### 2. 日付列 (`date`) の役割とは？

CSV に含まれる **`date` 列（例: `2026-07-26`）** は、単なるレース開催日のメモではありません。
これは、**「過去データ（基準値）」と「本日のデータ（検証対象）」を正確にグループ分け・分離・比較するための「タイムスタンプ・インデックス」** です！

```text
  【日付列 (date) を活用した過去データ vs 当日データの比較構造】

   全蓄積データ (data/parsed_races.csv)
     ├── 過去データ群 (date < 2026-07-26) ───> 【基準値 (Baseline)】
     │                                           1号艇平均着順: 1.85着, 平均勝率: 55.4%
     │                                                      │  (比較分析)
     └── 当日データ群 (date == 2026-07-26) ───> 【検証対象 (Target)】 
                                                 本日1号艇平均着順: 2.40着 (平常時より低迷!)
```

##### 3. 🚀【ステップバイステップ】過去データと比較分析を進める 4 つの手順

読者の皆さんが実際に過去データを取り込み、比較分析を行う具体的なステップは以下の通りです！

> [!TIP]
> **【実践ステップガイド】**
> 
> - **ステップ 1: 【データ蓄積】過去期間を一括ダウンロード**
>   - ターミナルで `mise run data:download:range` を実行し、開始日（例: `20260701`）と終了日（例: `20260725`）を入力して、過去数週間分の JSON を `data/raw/` に安全に蓄積します。
> 
> - **ステップ 2: 【全自動パース】Racket で集約 CSV を生成**
>   - `mise run parse:json` を実行します。`code/ch02-json-parser.rkt` が `data/raw/*.json` を全自動スキャンし、`date` 列が付与された統合 CSV (`data/parsed_races.csv`) が生成されます。
> 
> - **ステップ 3: 【データ分離】RacketFrames で「過去」と「本日」を抽出**
>   - 次章以降で学ぶ `df-filter` を使い、`date` 列をキーにして「過去30日間のベースラインデータ」と「本日のデータ」の 2 つのデータフレームに分離します。
> 
> - **ステップ 4: 【比較と傾向検出】数値とグラフで変化を検証**
>   - 過去の平均勝率やモーター連対率と、本日の実績値を比較し、「本日は荒れ模様の展開か？」「特定の選手が過去平均以上のパフォーマンスを出しているか？」を客観的な数値で判定します！

#### 2.5 【深掘り大盛り解説】統計学における「過去データの期間」＝「量」×「品質（鮮度）」の方程式

ここで極めて重要な疑問が浮かびます。
**「過去データは『カレンダー上の期間（1ヶ月？1年？）』で測るべきか、それとも『実際のレース数（件数 $N$）』で測るべきか？」**

結論から言いましょう。ボートレース特有の事情と統計学の原則を紐解くと、**【レース数（件数 $N$）こそが統計的精度の真の支配者】** であり、本書では **「ダウンロード管理は期間（日付）、統計計算はレース数（件数 $N$）」** を本線の設計として採用します！

---

##### 1. なぜボートレースでは「期間（日数）」だけでは不十分なのか？

ボートレースには他のスポーツや株価データと異なる大きな特徴があります。それは **「全国 24 競艇場の休催日（非開催期間）・メンテナンス期間の存在」** です！

- 例えば、特定の競技場（例: 桐生）のデータ分析をしようとした際、「過去1ヶ月間」を指定しても、その月に桐生がメンテナンスや日程の都合で 1 節（約6日間）しか開催していなければ、データ件数は極めて少なくなります。
- 逆に、連続開催されていた別の場（例: 住之江）の「過去1ヶ月間」は、レース件数が数倍に膨れ上がります。

つまり、カレンダー上の「過去 1 ヶ月」という期間は、**各競艇場や選手によって手に入るデータ件数（サンプル数 $N$）が大きく変動してしまう** のです。

---

##### 2. 「期間」と「レース数」の役割分担：本書の本線設計

| 判定レイヤー | 採用する基準軸 | なぜその軸を使うのか？（統計的・実用的な理由） |
|---|---|---|
| **① データ取得・保存レイヤー**<br>(`mise.toml` タスクランナー) | **【期間（日付 `YYYYMMDD`）ベース】** | API が日付単位で配信されており、ローカルストレージへの物理保存や `curl` 取得の管理単位として最も自然で扱いやすいため。 |
| **② 統計分析・計算処理レイヤー**<br>(Racket / RacketFrames) | **【レース数（件数 $N$）ベース】** | 統計学のすべての基本公式（大数の法則・平均値の標準誤差 $SE = \sigma / \sqrt{N}$・カイ二乗検定など）は、**カレンダーの日数ではなくレース数 $N$ のみに依存する** ため。休催日の影響を完全に排除して「同じ統計的信頼度」を担保できます。 |

---

> [!TIP]
> ### 📖 【中盛りコラム】自然環境（天候・風）を排除し、過去データを積み重ねる統計的・相関分析上の真の意義
> 
> API データに天候や風などの自然環境要素が含まれていないことは、一見するとデメリットに感じるかもしれません。しかし、**統計学やデータサイエンスの視点から見ると、これは「本質的な本気構造（相関関係）を取り出すための大きなアドバンテージ」** に変わります！
> 
> #### 1. 天候や風は「確率的なホワイトノイズ (ランダム誤差 $\epsilon$)」である
> 毎レースの突風や偶発的な雨・波の乱れは、平均するとプラスマイナスゼロに収束する **無作為なランダムノイズ（$\epsilon_i \sim \mathcal{N}(0, \sigma^2)$）** とみなすことができます。
> 単日の数レースだけを見ていると、この風や波のノイズが影響して「1号艇が強風に煽られて敗北した」といった偶発的事象に分析結果が振り回されてしまいます。
> 
> #### 2. 過去データを積み重ねることで「ノイズが相殺消去」される！
> 過去のレースデータを $N \gg 1$（数千〜数万件）と大量に蓄積すると、ランダムな自然環境ノイズの総和は平均化され、ゼロへ収束します（$\frac{1}{N}\sum \epsilon_i \approx 0$）。
> その結果、ノイズに隠されていた **「ボートレースの真の構造的相関関係」** がクリアに浮かび上がります：
> 
> 1. **「艇番 (boat_num) vs 確定着順 (rank)」の構造的相関**: どんな風が吹こうとも、1号艇が有利である確率的アドバンテージ。
> 2. **「モーター2連対率 (motor_rate) vs 確定着順 (rank)」の機力相関**: モーター性能が高い艇ほど着順が繰り上がる絶対的相関。
> 3. **「全国勝率 (win_rate) vs 確定着順 (rank)」の選手実力相関**: A1級レーサーが上位に入着する実力相関。
> 
> **「あえて天候ノイズに惑わされず、過去データを積み重ねて本質的な相関関係を取り出す」** ――これこそが本書で実践する統計アプローチの醍醐味です！

##### 3. ボートレース統計分析における推薦期間・レース数一覧表

目的別の最適な「期間」と「レース数 $N$」の目安です。

| 取得期間の目安 | 目安レース件数 ($N$) | 「量 (件数 $N$)」の評価 | 「品質 (鮮度)」の評価 | 最適な分析用途・おすすめ活用シーン |
|---|---|---|---|---|
| **直近 10 レース〜 1 節間 (約6日間)** | **$N = 10 \sim 1,000$** | ❌ 小（ノイズが残る） | ⭕️ **極高（超直近）** | レーサーの「今節の調整力」や「当節モーターのリアルタイム気配」の微細なチェック用 |
| **過去 1 ヶ月〜 3 ヶ月間** ⭐ | **$N \approx 8,000 \sim 25,000$** | ⭕️ **大（統計的に十分）** | ⭕️ **最高（同シーズン・現級位）** | **【黄金推奨スウィートスポット！】<br>相関分析・RacketFrames集計・第6章予測モデルの構築にベスト！** |
| **過去 6 ヶ月〜 12 ヶ月間 (1年間)** | **$N \approx 50,000 \sim 100,000$** | ⭕️ 極大（大数の法則成立） | ⚠️ 中（モーター交換・昇級等の環境変化あり） | 枠番ごとの全国勝率や競艇場別のインコース1着率など、マクロな全体真確率の抽出用 |

> [!CAUTION]
> ### 💡 結論：データ分析の決定版黄金法則
> 
> - **物理取得** は `mise run data:download:range` で **過去 1〜3 ヶ月間（日付）** を一括蓄積！
> - **統計処理** は RacketFrames で **直近 $N$ レース（例: 各レーサー直近 30 レース、全体直近 5,000 レース）** をカウント抽出して集計！
> 
> この「期間で集めて、件数 $N$ で解く」アプローチこそが、休催日の偏りを排除したプロのデータサイエンス手法です。

> [!NOTE]
> ### 🔮 次章以降への予告：過去データはグラフや予想モデルでこう使われる！
> 
> 本章でせっせと過去データを蓄積・比較可能にした理由は、**第 3 章〜第 6 章のクライマックスで過去データが主役になるから** です！
> 
> - **第 3 章（RacketFrames 入門）**:
>   `date` 列を使って過去数週間分の膨大な CSV から特定の開催日や特定の選手データをサクッとフィルタリングする基礎技術を習得します。
> - **第 4 章（統計と集計分析）**:
>   `df-groupby` を使い、枠番ごとの平均確定着順や勝率を集計します。過去データ数千件があるからこそ、標準偏差（ばらつき）が小さくなり、信頼できる平均値が算出されます。
> - **第 5 章（データの可視化・プロット）**:
>   「モーター2連対率 vs 確定着順」の散布図 (`df-plot-scatter`) を描画します。1日分のデータ（数個の点）だとグラフがスカスカで傾向が見えませんが、過去データを重ね合わせることで、**「モーター性能が高いほど着順が良くなる（右下がり）」の見事な相関曲線** が画面に浮かび上がります！
> - **第 6 章（予想モデルの構築と的中率テスト【最大クライマックス】）**:
>   過去データから算出された「枠番アドバンテージ」と「選手の過去勝率」「モーター連対率」を `df-join`（テーブル結合）でガッチャンコ組み合わせ、本日のレースの **予想スコア** を計算します。過去データという「答え」があるからこそ、モデルの予測的中率を答え合わせ検証できるのです！
> 
> 統計学におけるすべての分析・予想の根幹は **「過去データとの比較」** にあります。この視点を持って、次章からのデータフレーム操作に進みましょう！

#### 2.6 章のまとめ：三角ロジックによる整理

* **【主張 (Claim)】**: ダウンロードは期間単位で行い、統計計算は直近$N$レース（件数$N$）で切り出す2層パイプラインこそが、最も高品質な分析環境を提供する。
* **【事実・データ (Fact)】**: `mise run data:download:range`によるJSON蓄積と、`code/ch02-json-parser.rkt`による`date`列付与累積CSV（`parsed_races.csv`）の自動生成。
* **【論拠・理由付け (Reasoning)】**: 競艇場の休催日によるサンプル数の偏りを件数$N$の抽出で排除しつつ、大量データ蓄積により自然環境ノイズを相殺消去して本質的相関を取り出せるため。
