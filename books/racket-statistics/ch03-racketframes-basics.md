#### 3.1 そもそも「データフレーム」ってなに？

みなさんは Excel（エクセル）や Google スプレッドシートで、下のような「表」を見たことがありますよね。

```text
  【普段私たちがよく見る「表」のイメージ】

  +------+----------+----------+----------+
  | 行   | 選手名   | 全国勝率 | 艇番     |  <-- 列（項目名）
  +------+----------+----------+----------+
  | 0    | 峰竜太   |   0.85   |    1     |
  | 1    | 毒島誠   |   0.81   |    2     |
  | 2    | 瓜生正義 |   0.72   |    3     |
  +------+----------+----------+----------+
    ^
  行番号（見出し）
```

Racket の世界で、この **「縦と横に綺麗に並んだ表データ」** をそのまま扱うための仕組みが **「DataFrame（データフレーム）」** です。

Racket でデータフレームを読み込むのは、たったの 2 行で完了します。

```racket
#lang racket
(require racketframes)

;; CSVファイルを読み込んで「表（df）」を作る
(define df (read-csv "data/parsed_races.csv"))

;; 表の概要（何行・何列あるか）を画面に出す
(df-summary df)
```

> **💡 【コラム】「Excel マクロ」ではなく、なぜ R や RacketFrames なのか？**
> 
> 「Excel もマクロ（VBA）で自動化できるのでは？」と思うかもしれません。確かに自動化は可能ですが、以下の決定的な違いがあります。
> 
> 1. **一般的メリット（安全性と管理しやすさ）**: Excel マクロはセルの誤上書きやファイルの破損リスクがありますが、R や RacketFrames は元データを破壊しない「安心設計（関数型）」です。また、コードがテキストなので Git で完璧にバージョン管理できます。
> 2. **ボートレースでのメリット**: 毎日増え続ける大量のレース結果を、元のデータを汚すことなく安全・高速に集計し、いつでも正確に計算結果を再現できます！

#### 3.2 RacketFrames をつくる「3つの主要なパーツ」

データフレームの内部は、実は **「3つの主要パーツ」** が組み合わさってできています。

```text
+-----------------------------------------------------------------------+
|                       1. DataFrame (表全体)                           |
|                                                                       |
|  +-----------------------------------------------------------------+  |
|  |  2. Index (行の見出しタグ / 背番号)                             |  |
|  |     [ 0,  1,  2,  3,  ... ]                                     |  |
|  +-----------------------------------------------------------------+  |
|  |  3. Series (縦1列のデータグループ)                              |  |
|  |     • 列A: "racer_name" -> CSeries ["峰竜太", "毒島誠", ...]    |  |
|  |     • 列B: "win_rate"   -> NSeries [0.85, 0.81, ...]          |  |
|  |     • 列C: "boat_num"   -> ISeries [1, 2, ...]                  |  |
|  +-----------------------------------------------------------------+  |
+-----------------------------------------------------------------------+
```

1. **DataFrame（データフレーム）**: 縦と横を組み合わせた「表全体」の箱。
2. **Index（インデックス）**: 各行にペタッと貼られた「行番号の見出しタグ」。
3. **Series（シリーズ）**: 縦1列に並んだ「同じ種類のデータの束（たば）」。

この 3 つが協力することで、大量のデータを間違えずに素早く計算できます。

---

#### 3.3 Series（シリーズ）は「縦1列のデータ専門チーム」

「シリーズ（Series）」とは、表の **縦1列（縦の列）** のことです。
RacketFrames では、扱うデータの種類（文字か、整数か、小数か）に合わせて、以下の **3つの主要な専門チーム** が用意されています。

```text
  【縦1列（シリーズ）の主な種類と専門分野】

    ① ISeries（整数専門）        ② NSeries（小数・数値専門）     ③ CSeries（文字・名前専門）
   +--------------------+      +--------------------+      +--------------------+
   | 艇番 (boat_num)    |      | 全国勝率 (win_rate)|      | 選手名 (racer_name)|
   +--------------------+      +--------------------+      +--------------------+
   | 1                  |      | 0.85               |      | "峰竜太"           |
   | 2                  |      | 0.81               |      | "毒島誠"           |
   | 3                  |      | 0.72               |      | "瓜生正義"         |
   +--------------------+      +--------------------+      +--------------------+
   (Fixnum = 整数の数字)        (Flonum = 小数の数字)       (Categorical = 文字列)
```

* **`ISeries` (アイ・シリーズ)**: 1, 2, 3 のような「整数の数字」専門。
* **`NSeries` (エヌ・シリーズ)**: 0.85 や 52.4 のような「小数の数字」専門。平均値などの計算が得意！
* **`CSeries` (シー・シリーズ)**: 選手名や会場名などの「文字（名前）」専門。

この型分離により、ハイスピードな計算が可能になります。

#### 3.4 Index（インデックス）の秘密：図書カードと自動位置合わせ

「インデックス（Index）」は、データを探すための **「見出しタグ（図書カード）」** のような役割を持っています。

```text
  【インデックスがあるから一瞬で見つかる！】

     Index (見出しタグ)            データの行
       [ 0 ] --------------> 0行目: 峰竜太 選手
       [ 1 ] --------------> 1行目: 毒島誠 選手
       [ 2 ] --------------> 2行目: 瓜生正義 選手
```

##### 秘密①: $O(1)$ の一瞬アクセス（定数時間検索）
インデックスがあるおかげで、10万行ある巨大なデータからでも、目的の行を **瞬時（0.001秒以下）** に引っ張り出すことができます。

##### 秘密②: 自動位置合わせ（アラインメント）
もし、順番がバラバラな2つの列を足し算しようとしても、インデックスが自動的に同じタグ同士をマッチングして計算してくれます。

---

#### 3.5 データフレームのルールと注意点

データフレームを安全に扱うために、知っておくべき **「2つの大事なルール」** があります。

1. **すべての列（Series）は同じ長さで揃える！**
2. **マス（セル）を直接書き換えない！（関数型の安心設計）**

---

#### 3.6 欠損値 `RFNoData`（空欄データ）の自動スキップ

実際のデータには、データが抜け落ちている「空欄（欠損値）」が含まれることがあります。RacketFrames では空欄のことを **`RFNoData`（アールエフ・ノーデータ）** と呼び、平均値などを計算するときに自動でスキップしてくれます。

#### 3.7 🔥 【重要新ステップ】期間累積データから「直近 N レース (サンプルサイズ N)」を厳密スライス抽出する（`df-take-recent-races`）

前章で学んだ通り、**「ダウンロードは日付（期間）だが、統計の信頼性を決めるのはレース数 $N$」** でした。
各競艇場の休催日（非開催期間）によるデータの偏りを解消するため、蓄積された全 CSV データから **「直近 N レース分だけを件数基準でスライス抽出するステップ」** を導入します！

```text
  【3ステップ：期間累積 CSV から「直近 N レース」を切り出す集積構造】

   [Step 1: 期間ダウンロード] ───> 日付別JSON (data/raw/YYYYMMDD.json)
                                         │
   [Step 2: 全自動結合]       ───> 全累積CSV (data/parsed_races.csv: 例 30日分 = 8,000レース)
                                         │
   [Step 3: N件スライス]      ───> (df-take-recent-races df 1000)
                                         │
                                         ▼
                                  【厳密なサンプルサイズ N = 1,000 レース完成！】
                                  (競艇場の休催日による偏りが完全に消去される)
```

##### スライス抽出の Racket 実装ロジック (`code/ch03-racketframes-basics.rkt`)

```racket
#lang racket
(require racketframes)

;; 期間蓄積データから「直近 N レース」のみを件数基準で切り出す本線関数
(define (df-take-recent-races df n-races)
  (define rows (second df))
  (if (null? rows)
      rows
      (let ()
        ;; 1. レース一意キー (date + stadium_num + race_num) ごとにグループ化
        (define race-groups (make-hash))
        (for ([r rows])
          (define key (format "~a-~a-~a" (hash-ref r "date" "") (hash-ref r "stadium_num" 0) (hash-ref r "race_num" 0)))
          (hash-update! race-groups key (lambda (lst) (cons r lst)) '()))
        
        ;; 2. 日付・レース番号順でソート（新しい順）
        (define sorted-keys (sort (hash-keys race-groups) string>?))
        
        ;; 3. 指定の直近 N レース分だけキーを選択
        (define target-keys (take sorted-keys (min n-races (length sorted-keys))))
        
        ;; 4. 対象レースの全艇データを行リストとして結合して返す
        (apply append (map (lambda (k) (hash-ref race-groups k)) target-keys)))))
```


この `df-take-recent-races` 関数によって、どんな期間でダウンロードしたデータであっても、常に **数学的に一定のサンプルサイズ $N$** を切り出して統計計算に回すことができます！

#### 3.8 【深掘り考察】RacketFrames の設計思想まとめ

```text
  +-------------------------------------------------------------------------+
  |              RacketFrames が初心者に優しい 5つの理由                    |
  +-------------------------------------------------------------------------+
  | 1. シンプルな文法 : 表操作に集中できる                                 |
  | 2. Index の安心感 : データの順番がずれても、自動で正しくマッチング      |
  | 3. 計算の自動整列 : 2つの列を足し算するときも、番号を自動で揃えてくれる  |
  | 4. 外部連携が簡単 : CSV, JSON からそのまま読み込める                   |
  | 5. 件数スライス機能: 休催日の偏りを消去し直近 N レースを厳密抽出         |
  +-------------------------------------------------------------------------+
```

#### 3.9 実践：綺麗なデータを抽出してみよう！

それでは、学んだ仕組みを使って、必要な列だけを抜き出してみましょう。

```racket
#lang racket
(require racketframes)

;; 1. CSVファイルを読み込む
(define df (read-csv "data/parsed_races.csv"))

;; 2. 直近 100 レース (件数 N) をスライス切り出し
(define df-recent-100 (df-take-recent-races df 100))

;; 3. "racer_name", "win_rate", "rank" の3列だけを安全に抜き出す (df-project)
(define df-clean (df-project df-recent-100 '("racer_name" "win_rate" "rank")))

;; 4. 結果を画面に表示
(df-summary df-clean)
```

次章では、この「直近 $N$ レース抽出データ」を使って、平均や勝率の本格的な統計計算を行っていきます！
