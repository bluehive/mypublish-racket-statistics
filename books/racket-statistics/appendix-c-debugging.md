> **この付録のゴール**  
> プログラムが意図通りに動かない（文法エラーや型不一致）ときに、慌てず自力で解決するためのデバッグ手順と確認リストを手に入れる。  

#### C.1 エラーメッセージの読み方

Racket でエラーが発生した際、DrRacket の相互作用ウィンドウ（下段）に赤字でメッセージが表示されます。エラーメッセージは**「最後の行」から逆順に読む**のがコツです。

##### よくあるエラーメッセージと対処法

1. **`read-syntax: expected a ')' to close '('`**
   * **原因**: 閉じ括弧 `)` が足りません。
   * **対処**: 括弧のペアを確認します。DrRacket で括弧の上にカーソルを置くと、対応する括弧がグレーでハイライトされます。
2. **`unbound identifier: win-rate`**
   * **原因**: `win-rate` という名前の変数や関数が定義されていません（スペルミスや、Run ボタンを押し忘れている状態）。
   * **対処**: つづりを確認するか、上部の **Run** ボタンを押してプログラムを再読み込みしてください。
3. **`contract violation: expected <number?>, given <string?>`**
   * **原因**: 数値が必要な計算（例： `+` や `df-mean`）に、誤って文字列データが渡されています。
   * **対処**: データフレームの列のデータ型（`ISeries`/`NSeries` か `CSeries` か）を確認してください。

#### C.2 相互作用ウィンドウ（REPL）での対話的トラブルシューティング

全体を一度にデバッグしようとせず、小さな部分に切り分けて相互作用ウィンドウで実行してみましょう。

1. **小さな式だけで評価してみる**:
   ```racket
   (+ 1 2)  ; ← 動作するか？
   ```
2. **データフレームの1行目だけ取り出して中身を見る**:
   ```racket
   (first (df-rows df))
   ```

#### C.3 困ったときのチェックリスト

* [ ] 先頭に `#lang racket` が書かれているか？
* [ ] 定義ウィンドウを変更した後、**Run** ボタンを押したか？
* [ ] CSV ファイルのパス（例: `"data/races.csv"`）が正しい場所を指しているか？
* [ ] 括弧の開閉数が一致しているか？
